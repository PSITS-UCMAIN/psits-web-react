## 1. Overview

The PSITS Web client employs a modern, clean aesthetic with a professional yet approachable tone. The design emphasizes clarity and usability through generous whitespace, soft rounded corners (pill-shaped buttons), and subtle shadows. The color palette centers around a vibrant sky blue primary color (#1C9DDE) paired with neutral grays, creating a contemporary tech-forward appearance. The design density is balanced—spacious enough for readability while maintaining efficient information presentation. Visual treatments include glassmorphism effects (backdrop-blur), smooth animations, and a consistent rounded aesthetic throughout.

## 7. Component Conventions

### Buttons

**Variants:**
- `default`: Primary blue background (`bg-primary`), white text, pill-shaped (`rounded-full`)
- `destructive`: Red background, white text
- `outline`: White background with border, hover accent
- `secondary`: Light gray background (`bg-secondary`)
- `ghost`: Transparent, hover accent background
- `link`: Text-only with underline on hover

**Sizing:**
- `default`: `h-9 px-4 py-2`
- `sm`: `h-8 px-3` with `rounded-md`
- `lg`: `h-10 px-6` with `rounded-lg`
- `icon`: `size-9` (square)

**States:**
- Hover: Slight opacity reduction (`hover:bg-primary/90`)
- Active: Scale down (`active:scale-95`)
- Focus: Ring with primary color (`focus-visible:ring-ring/50`)
- Disabled: Reduced opacity, no pointer events

**Border radius:** `rounded-full` (pill-shaped) is the default

### Cards / Panels

- Background: `bg-card` (white)
- Border: `border border-gray-100` (subtle)
- Border radius: `rounded-xl` (12px)
- Shadow: Minimal or none by default
- Padding: `p-6` for content areas
- Structure: Compound component pattern (Card, CardHeader, CardTitle, CardDescription, CardContent, CardFooter)

### Form Inputs

**Default Input:**
- Height: `h-9` (36px)
- Border: `border-input` with `rounded-md`
- Background: Transparent or `bg-input/30` in dark mode
- Padding: `px-3 py-1`
- Focus: 3px ring with primary color (`focus-visible:ring-ring/50`)
- Placeholder: `text-muted-foreground`
- Error state: Red border and ring (`aria-invalid:border-destructive`)

**Floating Label Pattern:**
- Used in LoginForm
- Label positioned absolutely, transitions on focus/filled
- Placeholder must be a space for CSS `:placeholder-shown` to work
- Border radius: `rounded-xl` for auth forms

**Input Group Pattern:**
- Wrapper: `.input-group` with `mb-4 flex flex-col gap-1.5`
- Label: `.input-label` with `text-sm font-medium`
- Field: `.input-field` with full styling
- States: `.error`, `.success`, `.focus` classes modify label and field colors

### Badges / Tags

- Size: `text-xs` with `px-2 py-0.5`
- Shape: `rounded-full`
- Variants: `default` (primary), `secondary`, `destructive`, `outline`

  - Library: Lucide React (primary)

  - Pointer events disabled: `[&_svg]:pointer-events-none`
  - Consistent sizing: `[&_svg:not([class*='size-'])]:size-4`

## 10. Naming Conventions

- **CSS classes**: 
  - Utility-first (Tailwind)
  - Custom utilities in `@layer utilities`
  - Component classes in `@layer components` (`.btn`, `.input-group`, etc.)
  
- **Component files**: 
  - PascalCase (e.g., `Button.tsx`, `LoginForm.tsx`)
  - UI components in `components/ui/`
  - Feature components in `features/[domain]/components/`
  
- **Token names**: 
  - CSS custom properties with `--color-` prefix
  - Kebab-case (e.g., `--color-primary-500`, `--radius-lg`)
  - Semantic naming (e.g., `--color-success`, `--color-destructive`)
  
- **Data attributes**: 
  - Used for component slots: `data-slot="button"`, `data-slot="card-header"`
  - Used for variants: `data-variant="default"`, `data-size="lg"`
  - Used for states: `data-invalid`, `data-state="open"`

## 11. Do's and Don'ts

### Do
- Use `rounded-full` for buttons to maintain the pill-shaped aesthetic
- Apply `active:scale-95` to interactive elements for tactile feedback
- Use the `cn()` utility function to merge Tailwind classes properly
- Leverage Radix UI primitives for accessible components
- Use `data-slot` attributes for component part identification
- Apply focus rings with `focus-visible:ring-ring/50 focus-visible:ring-[3px]`
- Use the floating label pattern for auth forms
- Maintain consistent spacing with Tailwind's spacing scale
- Use Framer Motion for complex animations, CSS transitions for simple ones
- Keep shadows subtle and minimal
- Use semantic color tokens (`--color-primary`, `--color-success`) rather than raw values

### Don't
- Don't use sharp corners on buttons (avoid `rounded-md` or `rounded-none`)
- Don't create custom color values outside the defined palette
- Don't bypass the `cn()` utility when combining classes
- Don't use inline styles when Tailwind utilities exist
- Don't create heavy shadows or excessive visual weight
- Don't use `any` type in TypeScript components
- Don't mix styling approaches (stick to Tailwind + CSS variables)
- Don't create one-off animations without considering reusability
- Don't ignore the compound component pattern for complex UI elements
- Don't use fixed pixel values when spacing tokens exist

## 12. Open Questions / WIP

### Inconsistencies Found

1. **Border Radius Variance**: 
   - Buttons use `rounded-full` (pill-shaped)
   - Cards use `rounded-xl` (12px)
   - Inputs use `rounded-md` (6px) in most places but `rounded-xl` (12px) in auth forms
   - Dialogs use `rounded-lg` (8px)
   - **Recommendation**: Document when to use each radius value or standardize further

2. **Shadow Usage**: 
   - Most cards have `shadow-none` or minimal shadows
   - Header uses custom shadow `shadow-[0_8px_30px_rgb(0,0,0,0.04)]`
   - Buttons sometimes have `shadow-sm` or `shadow-md`
   - **Recommendation**: Create named shadow tokens for consistency

3. **Input Styling Patterns**: 
   - Two distinct patterns exist: standard input and floating label input
   - Standard: `h-9` with `rounded-md`
   - Floating label: `h-12` with `rounded-xl`
   - **Recommendation**: Document when to use each pattern

4. **Animation Duration**: 
   - Multiple duration values used (150ms, 200ms, 300ms, 350ms)
   - No clear guideline on which to use when
   - **Recommendation**: Create animation duration tokens

5. **Dark Mode**: 
   - Dark mode tokens defined for sidebar but not fully implemented across all components
   - Some components have `dark:` variants, others don't
   - **Recommendation**: Complete dark mode implementation or remove partial support

6. **Icon Sizing**: 
   - Multiple size values used (`size-4`, `size-5`, `size-6`, `h-5 w-5`, etc.)
   - No clear hierarchy or usage guidelines
   - **Recommendation**: Standardize icon sizes by context (inline, button, header, etc.)
