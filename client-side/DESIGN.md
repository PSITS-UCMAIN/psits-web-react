## 11. Do's and Don'ts

### Do
- Use Tailwind utility classes for all styling
- Apply Framer Motion for interactive animations (hover, tap, transitions)
- Use `font-primary` (Montserrat) for body text and `font-secondary` (League Spartan) for special headings
- Implement responsive design with Tailwind breakpoints (`sm:`, `md:`, `lg:`)
- Use PropTypes for component prop validation
- Apply `backdrop-blur` for overlays and sticky elements
- Use React Icons for consistent iconography
- Implement smooth transitions (300ms default)
- Use semantic color names from Tailwind config (`primary`, `secondary`, `accent`)

### Don't
- Don't use inline styles or CSS modules (stick to Tailwind)
- Don't create custom CSS classes unless absolutely necessary (use Tailwind utilities)
- Don't mix Font Awesome and React Icons unnecessarily (prefer React Icons for new work)
- Don't use `any` type in TypeScript (this is a JS project, but principle applies)
- Don't hardcode colors — use Tailwind config tokens
- Don't create new spacing values without adding to Tailwind config
- Don't use `!important` in Tailwind classes unless handling third-party overrides

3. **Semantic colors incomplete:** No explicit `success`, `warning`, or `error` colors defined in Tailwind config. Error states use Tailwind's default `red-500/600`. Consider adding semantic color tokens for consistency.

4. **Icon library duplication:** Both React Icons and Font Awesome are installed. Font Awesome appears in older components (e.g., `NotFound.jsx` uses `fa fa-exclamation`), while newer components use React Icons. Consider standardizing on React Icons for consistency.

5. **Animation naming:** The `spinGlow` animation is specific to the raffle feature. Consider documenting other custom animations if they exist elsewhere in the codebase.

6. **Responsive text sizing pattern:** `FormInput.jsx` uses `text-sm sm:text-base` for responsive sizing, but this pattern is not consistently applied across all components. Consider standardizing responsive text sizing.

7. **Button variants:** Only one button style is defined in `Button.jsx` (dark slate). Other button variants (primary, secondary, outline, ghost) may exist in other components not sampled. A comprehensive button variant audit is recommended.

8. **Toast/notification styling:** React Toastify is configured in `App.jsx` with `theme="colored"`, but specific toast styling is not documented. Consider documenting toast color schemes and positioning.

### Recommendations

- **Create a design tokens file:** Consolidate all color, spacing, and typography tokens into a single `tokens.js` or `design-tokens.ts` file for easier maintenance.
- **Document shadow scale:** Define and document the `.shadow-custom` value in Tailwind config.
- **Standardize icon library:** Migrate all Font Awesome icons to React Icons for consistency.
- **Add semantic colors:** Define explicit `success`, `warning`, `error`, and `info` colors in Tailwind config.
